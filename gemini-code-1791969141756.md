# Project Specification: Workload-Aware GPU Power Allocation Simulator (MVP Demo)

## 1. Project Overview & Core Value Proposition
Build an interactive, enterprise-grade web application using **React (TypeScript), Tailwind CSS, Lucide Icons, and Recharts**.
This simulator demonstrates a core algorithmic breakthrough for AI Data Centers facing grid curtailment (e.g., ERCOT 4CP / Demand Response events):
> **"Why Uniform GPU Power Capping Fails, and How Workload-Aware Power Allocation Preserves SLA While Achieving Grid Targets."**

### Key Technical Insights to Demonstrate:
1. **Power Limit $\neq$ Actual Power Draw**: Memory-bound workloads (like LLM Decode) draw only 150W–300W even when the GPU Power Limit is set to 700W. Lowering their Power Cap to 500W yields **0W of actual power reduction** ("The Illusion of Power Capping").
2. **Non-linear Power/Performance Pareto Curve**: Based on published Dell PowerEdge XE9680 (8x H100 SXM, Llama 2 70B) benchmarks, lowering GPU power limit from 700W to 600W reduces actual server power by ~15% while losing only ~6% throughput (efficiency improves from 2.530 to 2.776 Tokens/s/W).
3. **Honest Engineering Boundaries**: Strictly separate `published_benchmark`, `interpolated`, and `assumption` data sources. Clearly output **Unmet Power Reduction (MW)** when GPU Tier-1 power capping hits SLA boundaries, and calculate the required **BESS (Battery Energy Storage System)** discharge to close the gap.

## 2. Tech Stack & UI/UX Design Requirements
- **Framework**: React 18+ with TypeScript (Vite or Next.js SPA structure, all logic running client-side for instant zero-latency interactive demo).
- **Styling**: Tailwind CSS. Use a sleek **Dark Mode Industrial/Enterprise Energy OS theme** (Background: `#0B1120`, Panels: `#111C2D`, Borders: `#1E293B`, Accent Blue: `#3B82F6`, Emerald Green: `#10B981`, Warning Amber: `#F59E0B`, Danger Red: `#EF4444`).
- **Charts**: `recharts` for side-by-side strategy comparisons, power-performance curves, and ERCOT time-series curtailment simulation.
- **Icons**: `lucide-react`.

## 3. Core Architecture & Data Structures (`src/types/simulator.ts`)

Implement the exact architectural abstractions defined below:

```typescript
export type DataSourceType = 'published_benchmark' | 'interpolated' | 'assumption' | 'unavailable';

export interface GPUProfile {
  id: string;
  gpu_model: string;
  platform: string;
  power_capability: {
    min_limit_w: number;
    max_limit_w: number;
    default_limit_w: number;
  };
  source_url: string;
}

export interface PowerPerfPoint {
  power_limit_w: number;
  estimated_actual_power_w: number;
  efficiency_tokens_per_s_w?: number;
  relative_throughput_pct: number; // 100% at default limit
  estimated_latency_impact_pct: number | null; // null if unavailable
  source_type: DataSourceType;
}

export interface WorkloadProfile {
  id: string;
  name: string;
  category: 'online_decode' | 'offline_inference' | 'pretraining';
  gpu_model: string;
  description: string;
  priority_weight: number; // 1 (lowest) to 10 (highest SLA sensitivity)
  default_max_perf_loss_pct: number; // SLA constraint boundary
  curve: PowerPerfPoint[];
  source_type: DataSourceType;
  source_citation: string;
  source_url: string;
}

export interface ClusterWorkloadGroup {
  workload_id: string;
  gpu_count: number;
  max_allowed_perf_loss_pct: number;
}

export interface AllocationNodeResult {
  workload_id: string;
  workload_name: string;
  gpu_count: number;
  baseline_power_limit_w: number;
  assigned_power_limit_w: number;
  baseline_actual_power_kw: number;
  predicted_actual_power_kw: number;
  actual_power_saved_kw: number;
  predicted_perf_loss_pct: number;
  sla_violated: boolean;
  source_type: DataSourceType;
}

export interface StrategyComparisonResult {
  strategy_name: 'No Optimization' | 'Uniform Power Capping' | 'Workload-Aware Allocation';
  total_baseline_power_kw: number;
  target_power_budget_kw: number;
  required_reduction_kw: number;
  achieved_reduction_kw: number;
  predicted_total_power_kw: number;
  unmet_power_reduction_kw: number; // Must be >= 0
  weighted_avg_perf_loss_pct: number;
  sla_violations_count: number;
  bess_required_kw: number;
  node_results: AllocationNodeResult[];
}
